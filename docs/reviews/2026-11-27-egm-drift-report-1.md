    - `scripts/` is not described at all: `render_results.py` (it regenerates README L47–136), `layout_audit.js` and `benchmark_dixon_coles.py`. The benchmark script is cited only in prose.
    - Neither are the webapp internals: `webapp/state.py`, `ui.py`, `pitch.py`, `icons.py` and `assets/`.
  - **"7 views" (L233).** `webapp/views/` has 12 view modules, and `app.py:33-51` registers 12 pages. That agrees with the README's own pages table (L382–395).
  - **"The 71 MB value booster is … not committed" (L234–235).** Three more boosters are also gitignored: `.gitignore:37` excludes `artifacts/market_value/*.lgb`, which covers `fair_value.lgb`, `forecast.lgb` and `fee.lgb`.
  - **"config.py: chronological split dates" (L214).**
    - The 2002-07 training start lives in `BURN_IN` in `sportpulse/pipelines/match_pipeline.py:34`, not in `config.py`.
    - The comment at `config.py:73` says "train: 2000-07 .. 2023-06". That contradicts both L256 and the code.
  - **"Tested package" / "unit tests … + artifact integration tests" (L208, L236).**

  - **"Edges past the bookmaker" (L20) is not enforced by the test that guards it.** `tests/test_artifacts.py:48` passes even when production RPS is up to 5e-4 *worse* than the market.

- **Club match model**
  - **Test window is stated two ways.**
    - L48 says "2024-07-01 → 2026-11-08, 17,054 matches". L256 says "test 2024-07 → 2026-09".
    - The code's test window is open-ended (`match_pipeline.py:87`). `metrics.json data.test` = `["2024-07-01","2026-11-08",17146]` and `data.test_with_odds` = 17054.
    - All 17,054 scored matches fall before 2026-10; the last `monthly` bucket is 2026-09. L48 therefore pairs the count of scored matches with the end date of a larger set (`scripts/render_results.py:15-16`).
  - **"38 leagues" in the test window (L21, L48).**
    - 38 is `data.divisions`, which counts every division in the whole dataset.
    - `per_division` reports only 24 leagues, because of the n < 150 filter at `match_pipeline.py:144`.
  - **Match count in the v1 table (L206).** It says 238,854 matches to "Sept 2026". `metrics.json data.matches_total` = 238,934 and `last_date` = 2026-11-08, which matches L40 but not L206.
  - **"Then refit on all data" (L257).** The refit uses only matches from `BURN_IN` = 2002-07-01 onward (`match_pipeline.py:215`), giving `production.n_train` = 226,617. The 12,317 matches before July 2002 are left out.
  - **Second fundamentals booster is missing from the architecture (L225, L249–250).**
    - `outcome_fundamentals_plus.lgb` adds Transfermarkt club squad values `cv18_diff` and `cv11_diff` (`models/match_outcome.py:114-122,168-171`; `outcome_meta.json extra_fund_features`).
    - It produces the "SportPulse Fundamentals (no odds)" row (L55, L151), yet the README describes it only in experiment-log row L371.
    - The squad-value feature itself (`features/club_value.py`: top-18 sum and top-11 mean, point-in-time by month) is not in the L244–248 feature list.
  - **"Stage 1 … used when no odds exist" (L249–250).**
    - Without odds, the market-residual prior falls back to stage-1's raw, uncalibrated logits (`match_outcome.py:96-100`).
    - The production forecast is that prior plus the residual booster's correction (`:164-167`).
    - The no-odds number reported in the README comes from the separate `_plus` booster (`:168-171`), not from either of these.
  - **Goals model uses betting odds (L22, L226, L254).**
    - `GoalsModel` is trained on all features, including 11 `mkt_*` columns, `ah_line` and `mkt_str_*` (`match_pipeline.py:104`; `goals_meta.json features`). The "Poisson-DC goals model" row is therefore market-informed.
    - ρ is fitted only on the validation season and is not refit for production (`models/goals.py:103-119`).
  - **Undocumented features.**
    - A running market-implied team strength: `mkt_str_h`, `mkt_str_a` and `d_mkt_str` (`features/engine.py:74,124,133,152-153,210-211`).
    - Difference features (`d_*`).
    - Naive expected-goals form features `xh_*` and `xa_*` (`engine.py:126-135`).
    - `month`, `tier` and a `division` categorical (`engine.py:224`).
  - **"Training and serving features match" (L242–243) does not fully hold.**
    - At inference, the best-price probabilities are copied from the average-odds Shin probabilities (`inference.py:95-97`).
    - `mkt_p_o25` and `ah_line` are never filled, so they stay NaN.
    - The club-value lookup falls back to the latest month (`club_value.py:60`).
  - **"Shin de-vigging" (L223, L248).** O/U and Asian-handicap prices are de-vigged proportionally, not with Shin (`features/market.py:43-46`, used at `engine.py:150`).
  - **EWM windows "short ≈ 8, long ≈ 40" (L246).** The code uses α = 0.18 and α = 0.04 (`engine.py:39-40`). That is a span of about 10 and about 49, and the code comments say "8-10" and "40-50".
  - **"Optuna TPE-tuned" (L249) and `train all --trials 30` (L408).**
    - The committed artifacts were trained without tuning: `metrics.json tuning` = null.
    - The parameters are hard-coded defaults (`match_outcome.py:35-40`).
    - The CLI default is `--trials 0` (`train.py:16`), but the Leaderboard page hard-codes "Optuna TPE, 30 trials" (`webapp/views/leaderboard.py:74`).
  - **Team-name canonicalisation (L302–304).** The README describes specific renames. The code applies a general rule: within a country, every spelling with the same lower-case alphanumeric key becomes the most recent spelling (`data/loaders.py:38-53`). FPL-feed names that have no mapping are only logged (`loaders.py:81-84`).
  - **Undocumented cleaning rules in "download + cache + clean" (L215).** Out-of-range odds, overrounds and stats are set to NaN, shots-on-target above shots becomes NaN, and duplicate rows are dropped (`loaders.py:119-140`). Live-feed rows have no stats or odds (`loaders.py:70-71`).
  - **Dixon-Coles benchmark details (L144–145).**
    - The history window is 1,095 days, not "three seasons" (`scripts/benchmark_dixon_coles.py:28`).
    - League-months with fewer than 200 history matches are skipped, leaving 211 matches unscored.
    - Promoted teams get the average rating of the bottom quarter (`:102-105`).
    - ρ is fitted in a second step rather than jointly by MLE (`:67-68`).
  - **"Pi-ratings + Elo logistic, Constantinou & Fenton 2013" (L152).** The row is a logistic regression on `pi_gd` and `elo_diff/400` only (`match_pipeline.py:118-120`), not the published model.

- **Premier League player forecaster**
  - **Heads (L228 "points + 3 probability heads"; L265 "Four LightGBM heads").**
    - `models/fpl_model.py:29-38` trains 6 heads: it adds `p_play` and `pts_if_played`.
    - Production points blend them as `0.95·direct + 0.05·p_play·pts_if_played` (`fpl_model.py:166-169`; `metrics.json blend_w_direct` = 0.95).
    - The README's own L81 and L365 already describe this hurdle blend, so the architecture text contradicts the rest of the README.
  - **Fixture context (L263–264, "goals and shots on target for/against").**
    - Only shots-on-target *for* is used, for both sides: `ctx_team_sot` = `h_l_stf` and `ctx_opp_sot` = `a_l_stf` (`pipelines/fpl_pipeline.py:41,46`).
    - The undocumented `ctx_xg_for` and `ctx_xg_against` are naive goals-form averages, not xG (`engine.py:131-132`).
    - `ctx_team_pts`, `ctx_opp_pts` and `ctx_win_p` are also undocumented (`fpl_model.py:25-27`).
  - **"From the previous gameweek" (L262).** `price_change_5` spans 5 gameweeks (`fpl_model.py:110`).
  - **Undocumented features.**
    - Rolling stats for influence, creativity, threat, goals_conceded, starts, yellow_cards, played and played60.
    - Per-90 rates over the last 10 fixtures.
    - `days_since`, `apps_total`, `was_home` and `position`.
    - Team and opponent rolling FPL xG, plus xG and xA shares (`fpl_meta.json features`; `fpl_pipeline.py:107-128,166-168`).
  - **"Optuna-tuned heads: rejected" (L366).** `fpl_pipeline.py:188-190` still tunes the `p_play`, `pts_if_played` and `points` heads whenever `--trials` > 0. `train.py:31` passes `--trials` to the FPL pipeline, so the documented `train all --trials 30` (L408) trains the rejected configuration.
  - **`train fpl --refresh` = "pull the newest gameweek and re-project" (L409).**
    - It actually re-downloads every FPL season and the club-match CSV, and rebuilds the match engine.
    - It then retrains all heads and the research variant, re-runs the test evaluation, and overwrites `metrics.json` (`fpl_pipeline.py:141-146,192-196,313`; `data/fpl.py:101-103`).
  - **"Best-XI" means two different things.**
    - The leaderboard metric (L79–86) is the top 11 by prediction with no position or budget limits (`fpl_pipeline.py:131-134`).
    - The app's "budget-constrained best XI" (L390) is a greedy heuristic: £85m default, formation min/max, no limit of 3 per club (`webapp/views/fpl.py:78-96`). The app also shows a captain pick that the README doesn't mention.
  - **Beating FPL xP (L186–187) leaves out contrary artifact evidence.**
    - Per-gameweek Spearman among active players: `artifacts/fpl/metrics.json gw_spearman_active.xP` = 0.720 vs `pred` = 0.561.
    - In 2026-27, xP has the better best XI: `by_season.2026-27.top_xi_xP` = 4.964 vs `top_xi_model` = 4.882.
  - **Undocumented serving logic.**
    - Players with status i, s, u or n and no percentage are projected at 0.
    - The availability multiplier also scales `p_60`, `p_goal` and `p_assist` (`fpl_pipeline.py:274-280`).
    - Double-gameweek fixtures are not summed per player (`fpl_pipeline.py:78,93`).

- **StatsBomb analyst layer (xG, xT, styles, reports)**
  - **"2022–24 tournaments" / "2022–24 men's tournaments" (L28, L103, L124, L170, L193, L289).**
    - The hold-out set `RECENT` (`pipelines/analyst_pipeline.py:21-22`) also includes three domestic league seasons: "1. Bundesliga 2023/2024", "Ligue 1 2022/2023" and "Major League Soccer 2023".

  - **"xT … from 3.5M passes and carries" (L290).** `expected_threat(passes, carries, shots)` is called with every pass and every carry (`analyst_pipeline.py:41`): 3,836,550 + 3,007,953 ≈ 6.8M (`metrics.json data.passes`, `data.carries`). It also uses shots.
  - **"xG: LightGBM (Optuna-tuned)" (L284).** The parameters are hard-coded (`analysis/xg.py:35-40`), and the repo has no Optuna code for xG.
  - **"Unseen 2022–24 tournaments" (L28, L170).**
    - The temporal hold-out booster trains for `n_iter` rounds (`xg.py:134`).
    - `n_iter` is the mean best iteration from 5-fold GroupKFold over *all* non-penalty shots, hold-out shots included (`xg.py:96-107`). The hold-out set was therefore visible when the round count was chosen.
  - **Penalties are undocumented.** They are not modelled; each gets the empirical conversion rate (`xg.py:109-111`; `xg.penalty_rate` = 0.763).
  - **Ingest cleaning (L281–283).** Shoot-out removal and common-name mapping happen in the pipelines, not in ingest (`analyst_pipeline.py:31-33,67-72`; `analysis/vaep.py:54`). Ingest keeps period-5 events.
  - **Team style profile (L292–294).** `PROFILE_METRICS` has 15 metrics (`analyst.py:129-138`). "Pass completion" is not in the README but is used on the radar and in the strengths and watch-outs.
  - **Undocumented metric definitions.** These live only in code (`analyst.py:52-65,88-124`):
    - Possession is pass share, and field tilt is the share of final-third passes.
    - PPDA uses x < 72 and x > 48.
    - Long balls are passes over 32 yards from the defensive third.
    - The progressive-action rule.
    - Failed moves get zero xT.
  - **Units.** Metric labels say metres, e.g. "Pressure height (m)" (`analyst.py:132`), but the coordinates are StatsBomb yards.
  - **Match Analysis page (L298, L389).**
    - It also has a "VAEP ratings" tab: per-match ratings, best per 90, and the VAEP model check (`webapp/views/match_analysis.py:121-161`). This is the only place VAEP appears in the UI, and the README does not mention it.
    - It also has a top-shots table comparing SportPulse and StatsBomb xG (`:74-82`).
    - The in-app xG model card lists "nearest-defender distance and pressure count". It omits the visible goal share and lane-blocker features that L285–287 describe (`:171-173`).
  - **Opponent Report (L295–297, L388).** The page has a KPI row, a partial-coverage warning, xG by phase, an assist-type chart and a touch heat map, none of which the README mentions (`webapp/views/opponent_report.py:31-39,122-135`).

- **VAEP**
  - **"Karun Singh's xT grid" (L194).**
    - The baseline uses the repo's own 16 × 12 grid (`pipelines/vaep_pipeline.py:37-46` loads `artifacts/analyst/xt_grid.npy`).
    - That grid is fitted on all matches, test matches included (`analyst_pipeline.py:41`).
    - The baseline's "calibrated" model is a logistic regression on start xT, end xT × success, and shot/penalty flags.
  - **"Location-only LightGBM" (L130, L134, L195).** Its features are `["type","x","y","end_x","end_y","success"]` (`vaep_pipeline.py:29`), so it also uses action type and success.
  - **Features (L320–323).**
    - Distance and angle to goal are computed only for the current action (`analysis/vaep.py:88-89`), not for the two previous ones.
    - Undocumented extra features: under-pressure, phase of play, dx/dy/move length and period (`vaep.py:86-93`).
  - **"On-ball defensive actions" (L319).** The set includes "Foul Committed" and excludes Pressure and Dribbled Past (`vaep.py:22-23`).
  - **Undocumented logic.**
    - Values reset at a new period and after a goal (`vaep.py:159-161`).
    - Labels stay within the same period (`vaep.py:133-138`).
    - The minutes estimator differs from the analyst-layer one (`vaep_pipeline.py:49-59` vs `analyst.py:157-166`).
  - **Units.** The goal angle uses a 7.32 goal width (`vaep.py:63`) on yard coordinates, while xG uses 8-yard posts (`data/statsbomb.py:34`).
